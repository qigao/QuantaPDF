# QuantaPDF 2.20.0

## Added

- `quantapdf_composer_clip_id`.
- `quantapdf_composer_clip_options`.
- `quantapdf_composer_add_clip_path()`.
- A V2 `clip_id` tail on Composer graphics-state options.

## Semantics

Clip resources own copied generic path commands, a nonzero/even-odd clip rule,
and an optional displayed-space affine transform. An all-zero transform record
means identity; any explicit transform must be finite and non-singular.

Equal normalized clip geometry/rule/transform deduplicates to one clip ID.
Command bytes are charged to the Composer resource budget.

A clip is applied by referencing it from an immutable graphics state. This
keeps one operation attachment surface for opacity, blend mode, and clipping
across text, embedded text, glyph runs, images, and paths.

## Compatibility

Graphics-state V1 keeps its pre-2.20 ABI boundary and implies clip ID 0.
V2 appends a size_t-aligned clip ID. V1 and V2(clip=0) states are semantically
identical and deduplicate.

Operations using graphics states without clips retain the 2.18/2.19 content
shape.

## Backend

Clip points are numerically transformed from local displayed-page coordinates
to page PDF coordinates, followed by `W n` or `W* n`. The clip is emitted
inside the existing balanced operation `q/Q` scope. No persistent clip
`cm` is emitted, so the subsequent operation keeps its own transform.

## Qualification

Focused tests cover validation, ownership, negative-zero deduplication,
resource-budget failure, V1/V2 graphics-state identity, invalid clip IDs,
nonzero/even-odd clips, transformed coordinates, clip + alpha composition,
text/image/path consumers, scope isolation, PDFium rendering, deterministic
finish, and installed-package linkage.
