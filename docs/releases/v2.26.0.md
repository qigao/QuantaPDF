# QuantaPDF 2.26.0

## Added

Generic Composer PATH now supports an additive V4 displayed-space affine
transform.

`quantapdf_composer_path_options` appends:

```c
quantapdf_affine_transform transform;
```

The V1, V2 and V3 SIZE macros remain frozen at their historical ABI boundaries.

## Semantics

- callers using V1–V3 receive identity placement;
- an all-zero V4 transform record means identity;
- explicit identity is canonical identity;
- any other V4 transform must be finite and non-singular.

V1–V3 and V4(identity) emit no additional PDF `cm` operator.

For page height H and public displayed-space transform:

```text
X = a*x + c*y + e
Y = b*x + d*y + f
```

the PDF CTM is:

```text
[a, -b, -c, d,
 c*H + e,
 H*(1-d) - f]
```

## Native stroke behavior

The CTM is emitted inside the existing PATH `q/Q` scope before stroke/fill
state and path geometry. Therefore PDF itself transforms stroke width, dash
spacing/phase, caps, joins, fill geometry and Pattern paint.

No numerical pre-scaling of stroke or dash data is performed.

`quantapdf_composer_draw_path_dashed()` uses the same V4 option record; no
parallel transformed-dash API is introduced.

## Qualification

Focused tests cover V3/V4 identity byte equivalence, all-zero identity,
NaN/singular rejection, direct CTM evidence, non-uniform fill and dashed stroke,
gradient paint under CTM, PDFium rendering, deterministic output, and the
installed-package consumer.
