# QuantaPDF 2.27.0

## Added

- `quantapdf_composer_pattern_builder_fn`.
- `quantapdf_composer_tiling_pattern_options`.
- `quantapdf_composer_add_tiling_pattern()`.

The API returns the existing generic `quantapdf_composer_paint_id`, so PATH
fill/stroke paint attachment is unchanged.

## Builder model

A synchronous builder receives a temporary transparent one-page child Composer
with the configured tile dimensions. The builder may use existing Composer
primitives.

Successful content is deterministically serialized and deduplicated by:

- tile width/height;
- x/y step;
- normalized transform;
- exact child PDF bytes.

Only the retained snapshot bytes count against the parent resource budget.

## Backend

Tiling paint lowers to a colored PDF PatternType 1 stream containing an imported
Form XObject of the tile snapshot.

Public positive y_step denotes downward repetition and therefore lowers to a
negative PDF /YStep.

The page-specific Pattern Matrix converts the tile Form's native PDF
coordinates through the public displayed-space affine transform.

## Compatibility

No PATH ABI or drawing API changes in 2.27. Existing gradient paint lowering is
unchanged.

## Qualification

Focused tests cover validation/deduplication, Pattern dictionary inspection,
fill/stroke reuse, translated/rotated Pattern matrices, PDFium repeated-cell
rendering, deterministic finish, resource budgeting, and the installed-package
consumer.
