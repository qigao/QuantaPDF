# QuantaPDF 2.30.0

## Added

`quantapdf_composer_add_clip_intersection()` creates an immutable compound clip
from 2–64 existing clip IDs.

## Canonicalization

Nested intersections flatten to leaf path clips. Leaf IDs are sorted and
deduplicated, so equivalent intersection trees reuse one clip resource.

A duplicate-only intersection such as `A ∩ A` returns the original `A` ID.

## Ownership

Only the canonical leaf-ID array is copied by the compound resource. Its bytes
are charged to the normal Composer resource budget.

## Backend

Compound clips lower to sequential PDF clip operators inside the existing
balanced operation scope:

```text
<path A> W/W* n
<path B> W/W* n
...
```

Because PDF clipping is cumulative, this is exact intersection semantics and
does not require boolean path geometry.

## Compatibility

No draw API or option struct changes. Existing graphics-state `clip_id`
attachment is reused unchanged.

ABI major remains 2.

## Qualification

Focused tests cover validation, nested flattening/deduplication, mixed fill
rules, transformed components, exact resource-budget boundaries, PATH/Form
consumers, scope isolation, PDFium rendering, deterministic finish, and the
installed-package consumer.
