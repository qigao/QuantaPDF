# QuantaPDF 2.31.0

## Added

- `quantapdf_composer_soft_mask_id`.
- Alpha and Luminosity soft-mask modes.
- `quantapdf_composer_soft_mask_options`.
- `quantapdf_composer_add_soft_mask()`.
- A V3 `soft_mask_id` tail on Composer graphics-state options.

## Source contract

A soft mask references an existing Composer Form that must be a transparency
group.

The mask stores mode plus a displayed-space affine transform. The all-zero
transform record means identity; explicit transforms must be finite and
non-singular.

Equal Form/mode/transform tuples deduplicate.

## Compatibility

Graphics-state V1 and V2 ABI boundaries are unchanged.

V3 with soft_mask_id=0 is qualified byte-identically with the existing V2
state.

No draw-option structures or draw entry points change.

ABI remains v2.

## Backend

Soft masks lower to ExtGState `/SMask` dictionaries.

A page-sized isolated transparency Form wraps the source Form so the public
displayed-space transform is converted correctly for each page. Alpha masks use
`/S /Alpha`; luminosity masks use `/S /Luminosity`.

The source Form is imported privately through the soft-mask wrapper when it is
mask-only, so it need not appear in the page's ordinary XObject resources.

Masked ExtGState and wrapper Form objects are cached per page because page
dimensions participate in the transform.

## Qualification

Focused tests cover validation, deduplication, V2/V3 zero-mask identity, direct
soft-mask dictionary inspection, nested mask Forms, outer alpha composition,
Alpha/Luminosity PDFium rendering, deterministic finish, and installed-package
linkage.
