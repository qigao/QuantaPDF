# #269 — Private visible-IR device pixel preview (Phase 2, test-only)

Stacked on Draft #331. This is the **first explicit private pixel-producing**
application of the bounded page-device geometry from #329–#331. It is
deliberately compiled **only by an independent strict C11 CTest target**,
not by the production library, public SDK, installed examples, or release.

## Correct coordinate-space boundary

`quantapdf_graph_snapshot_page_composer_ir()` has **already** applied the
selected /MediaBox, /CropBox, /Rotate, and /UserUnit to both Paint and W/W*
Clip transforms. Its commands use the rebased Composer `(x,-source_y)`
basis and the option's float transform produces zero-origin **visible**
Y-down coordinates. Therefore device projection is just:

`x_device = (bitmap_width / visible_width_points) * x_visible`
`y_device = (bitmap_height / visible_height_points) * y_visible`

The bitmap extents are first `ceil(visible_points * DPI/72)`, with the
**exact** extents used for each axis, following #330. No raw Source→Display
affine is applied a second time to the already-normalized commands.

## Intentionally narrow admission

The positive v0 admits exactly one opaque Normal nonzero Fill Path under
exactly one nonzero W Clip, both five-command closed rectangles with an
identity original PDF content CTM. The source's effective page-only affine
must match both **already-mapped** Path and Clip float matrices exactly
within the existing source-lowering representation. This refuses shear,
extra content CTM, divergent Path/Clip mapping, requested rotation, Stroke,
cubic, even-odd W*, extra resources, unsupported DPI, and unqualified
non-conforming input. Those features need their own pixel/precision gates.

The adapter borrows the entire owned IR, makes stack-local projected
page/operation/clip metadata only, and calls the existing bounded
`quantapdf_ir_raster_scoped_operations_v1` consumer. No commands are
rewritten and no second owner is installed. It separately precharges eight
source rectangle edges × 16 geometric samples × bitmap pixels with
division-before-multiplication, validates exact/float point projection
within 1/4096 device pixel, RGBA byte/pixel caps and zeroes result slots
transactionally on rejection. It has no PDFium/QPDF dependencies.

## First synthetic conformance, not a published original-positive

The new pure C11 test covers 3 DPI × 3 UserUnit × 4 intrinsic quarter
rotations = **36 render-positive** configurations with nonzero CropBox
origins, separate Fill and W Clip source geometry, expected source-interior
and exterior RGBA pixels, double-invocation byte equivalence and untouched
source command/state bytes. 72 DPI images must be byte-identical to the
previous bounded scoped-operation consumer of the **same normalized IR**.
Negatives exercise second affine application, path/clip transforms that
diverge from the Graph page map, Stroke, sample caps, RGBA byte caps and
unsupported DPI. No external PDFs are generated by this test.

The synthetic acceptance alone is **not** a pixel-parity result for the
original upstream jsPDF or a second licensed independent producer. The
next stage must create an original-PDFium whole-page conformance test for
the *exact* selected-page source original, including scope changes, packed
paint alpha, paint/clip edge phases, repeat and zero-output rejects, on
Linux Release+ASan/UBSan, macOS and Windows. No formal corpus count
increase, #208 switch, publication, or merge is implied.
