# M2b.2s: private reverse sibling V5 qualification

The [M2b.2r Source stage](native-m2b2r-reverse-sibling-source.md) retains
original Image→Fill→Text with GS [1,1,2] after a real Q restores GS0 and a
new q/W/n defines the independent Text leaf2. This increment adds one private
admission entry to the same mixed-operation compiler. It requires exactly
that order and binding, two independent identity-space rectangle leaves,
two opaque Normal states and one RAW Image resource. Complete graph
validation precedes geometry allocation. The old forward sibling entry
continues to refuse reverse input; public prepared metadata remains closed.

The existing typed compiler resolves each operation's frozen GS/Clip once.
Text snapshots leaf2 through the same original-quadratic glyph∩Clip sample
path. Fill and Image snapshot projected leaf1 through the existing V1 4×4
visible mask. The same V5 owner, source-order compositor and page ledger
retain 8M aggregate samples/512 edges, fixed Image/Fill 1/8 sample shares
and 16-edge child limits. No second raster, post-raster alpha multiplication,
per-Clip ledger reset or changed historical allocation order is introduced.

Original RAW/Flate 147/148 retain their exact authored bytes and have
independent whole RGBA at 72/96/144 DPI. New originals 168/169 use an early
leaf covering Image/Fill and a different Text leaf with visible disjoint
and partial glyph/Clip samples at all three DPIs. Each original has nonempty
Text/Fill/Image coverage, glyph samples exclusive to each leaf, and visible
wrong-Text-root, wrong-Image/Fill-root and manufactured-intersection controls.
The newer pair additionally requires visible spurious ink from incorrectly
multiplying averaged glyph and Clip alphas at every DPI. Reference pixels
use unchanged original-quadratic glyph masks plus analytic authored rectangles;
neither Source IR nor a production Bitmap supplies the oracle.

At 96 DPI both newer originals fault every reached ledger-backed C11
allocation, require empty output/live bytes/reservations, preserve Source
snapshots and retry exact independent bytes. Source/full-placement/output
pixels, operations and peak live bytes have N/N−1 checks. Sample/edge
admission thresholds are measured and checked at N/N−1 under unchanged
shares. Twelve malformed graph/binding variants refuse before allocation.
A second execution cannot reset placement charges, while its first detached
output remains exact after compiled-owner disposal.

Repeated test reference calls now reuse immutable analytic values and return
detached copies. Only references derived from original glyph assets and
authored constants are cached per test thread; no Source, Context, IR,
allocation-fault result or rendered byte is cached. Rectangle W/W* swaps in
otherwise identical RAW/Flate fixtures denote identical sample sets. A local
comparison against the uncached reference verifies all 48 mode/DPI pairs'
complete RGB/RGBA and every control counter unchanged. Historical golden
assets, test cases, fault positions, numerical policies and timeouts remain
unchanged. Candidate CI and independent master CI after merge remain separate
acceptance evidence.

The existing sanitizer preset stays Debug, with assertions, debug symbols,
ASan/UBSan, nonrecovering UBSan and frame pointers, and now adds `-O1` for C
and C++. [Clang's ASan guidance](https://clang.llvm.org/docs/AddressSanitizer.html)
recommends at least this optimization level for reasonable runtime. The
accumulated fault/quota corpus exceeded its historical 40-second deadline
without optimization; no case, sanitizer check or deadline is removed or
relaxed. Optimized fault-injection observability is verified by the same
complete native suite.

Prepared metadata and actual public Bitmap calls still refuse all four
reverse originals at 72/96/144 DPI, then recover accepted single, forward
sibling and compound profiles in the same Context with independent RGB and
retained Bitmap lifetime checks. Public preparation, receipts and Bitmap
fault/lifetime qualification require their next increment. No public ABI,
test executable/registration, CI workflow or timeout changes. Wider Clip
graphs/contours, fonts and matrices stay open under #584/#580/#570/#208.
