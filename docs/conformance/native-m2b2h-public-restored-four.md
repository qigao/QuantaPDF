# Original Q-restored fourth Fill through public Bitmap

The public Source V10 adapter admits the bounded four-paint profile whose
first Text/Fill/Image operations hold one frozen W/W* root, followed by an
opaque red rectangle under the original Q-restored GS0. The complete prefix
and suffix are validated before selecting the private prepared route. Clip
vertices must align to whole pixels at the requested 72/96/144 DPI. The
unclipped suffix retains its authored physical coordinates, including
fractional 96-DPI edges.

The route uses the shared typed operation compiler and one existing V5
owner, ledger and compositor. The existing eight-edge/half-work suffix share
and numeric quotas remain unchanged. No public ABI or renderer is added.

Acceptance reuses three existing native executables:

- Public render: a genuine original QPDF stream at 72/96/144 DPI compares
  every RGB byte with reviewed glyph coverage and independent analytic
  4x4 Fill/Image/suffix references. Red ink outside the original Clip must
  survive Q. An excess Q refuses the whole page, followed by same-Context
  recovery. The retained 96-DPI Bitmap survives all source/Context handles.
- Source/OOM: the existing three-paint and new four-paint prepared routes
  share exhaustive tests of reached Source C allocations and ledger-backed
  C11 allocations. Each failure publishes empty IR or zero image/receipt;
  representative retries reproduce complete bytes. Source pixels, output
  pixels, authored operations, drawn pixels and peak live bytes have N/N-1
  checks. Four-paint sample/edge caps are measured at the admission boundary
  under the unchanged fixed child shares, followed by exact N/N-1 checks;
  this threshold is distinct from actual billed work.
- Context/OOM: the actual public render call checks Bitmap storage NOMEM
  and both reference-overflow positions at each DPI, balanced leases,
  full-byte retry, surviving Bitmap data and one final Context destruction.
  Existing UserUnit cases use the same test procedure.

Stage-specific Source/C11 faults use the existing private hooks. Context
faults exercise the actual public facade. Test registration, historical
timeouts and original references remain unchanged.
